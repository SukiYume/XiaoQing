# URL Parser 插件

为完整的单 URL 消息生成网页标题、描述和可选预览图。

## 触发方式

插件没有显式命令。Dispatcher 只有在清理后的消息整体匹配一个 `http://` 或 `https://` URL 时才调用 `handle_url()`；带附加文字、包含多个 URL 或由其他命令处理的消息不会进入本插件。

## 解析规则

- 标题来自 `<title>`，折叠多余空白后最多保留 200 个字符。
- 描述依次读取 `description`、`og:description`、`twitter:description`，最终最多 100 个字符。
- 图片依次读取 `og:image`、`twitter:image`，相对地址以页面最终 URL 为基准补全。
- 没有任何可用元数据时不发送消息；只有描述时使用“网页预览”作为非空标题。

## 网络与资源边界

- 页面和图片均使用独立的公共安全客户端，不使用应用共享会话、凭据、代理或环境代理。
- 每一跳都重新校验 URL、DNS 结果和重定向，拒绝私网、环回、本机及其他非公网目标。
- 输入 URL 最多 2048 个字符，确保标题、描述和原链接合并后仍在 QQ 单条文本预算内。
- HTML 最多 `2 MiB`；单张图片最多 `5 MiB`，只接受实际内容为 JPEG、PNG 或 WebP 的图片。
- 图片最多 2000 万像素、120 帧；同时最多处理 `4` 个网页预览。
- 页面失败时不返回预览；可选图片失败时仍保留已经解析出的文字摘要。

## 本地缓存

预览图存放在插件数据目录的 `url_previews/` 中，以图片 URL 的 SHA-256 命名。缓存最多 `128` 项、总计 128 MiB，7 天未使用的文件会自动清理。远端文件名不会参与本地路径构造。

该插件依赖网页提供标准 HTML 元数据。需要脚本执行、登录态或专有接口的网站可能无法生成预览。
