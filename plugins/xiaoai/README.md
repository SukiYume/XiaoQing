# 米家设备与小爱桥接

自动发现已登录账号的米家设备，按型号整理 MIoT 属性、动作和事件。管理员私聊可使用自然语言查询和控制，现有小青 Agent 可通过命令目录调用。温湿度直接读取传感器；天气使用 Open-Meteo。设备云端调用支持跨网络使用。

## 消息扫码登录

在实际运行 XiaoQing 的 Python 环境、项目根目录执行：

```powershell
python -m pip install -e ".[xiaoai]"
```

运行中的小青通过管理员 `/reload` 加载插件，然后在管理员私聊中发送：

```text
/小爱 登录
```

小青会单独私聊发送二维码。使用米家 App 扫码并确认登录，二维码最长有效 5 分钟。扫码成功后小青列出音箱，发送 `/小爱 选择 1` 完成绑定；选择阶段有效期为 5 分钟。`/小爱 状态` 可查看当前进度和音箱列表，`/小爱 取消登录` 可取消本次流程。选择和取消操作归登录发起人所有。同一时间允许一个扫码会话。重新发送登录命令会替换自己上一次流程。

初次登录默认使用中国大陆地区；可用 `/小爱 登录 de` 等形式指定地区，支持 `cn/de/i2/ru/sg/us`。已有配置默认沿用地区和静默设置。登录通过米家 DID 关联音箱，按设备型号查询 MIoT 规格，自动选择 `execute-text-directive` 动作及参数顺序。

二维码在内存中生成并使用敏感消息通道投递；登录链接和待绑定令牌保留在内存中。选择完成后保存正式配置。二维码过期、选择超时、取消、插件卸载或进程退出均结束当前流程。已保存配置持续保留。扫码和绑定只执行登录与只读发现。

## 自动续期与失效提醒

- 插件每 30 分钟检查一次米家和小爱服务的访问状态。
- 服务令牌距上次获取满 6 小时后，使用已有 `passToken` 自动换取新令牌并保存。6 小时是主动续期策略，实际有效期由小米服务决定。执行命令前也会检查令牌年龄。
- 遇到明确的服务授权错误时尝试一次续期；只读查询可在续期后重试一次。出粮等设备动作保持一次提交，结果不确定时提示核对实际状态。
- 续期成功后服务接口仍拒绝访问时，保留登录状态并提示稍后检查。失效提醒依据账号续期结果触发，每轮失效独立记录投递回执。
- 网络故障和临时服务错误保留原凭据，等待后续检查。小米要求重新授权时，小青向绑定人私聊提示 `/小爱 登录`。提醒发送成功后记录已通知；发送失败时在后续检查重试。
- `/小爱 续期` 可立即触发服务令牌更新。`passToken` 失效或需要额外验证时使用 `/小爱 登录`。
- 通过消息绑定的用户自动成为提醒接收人。旧版终端配置在管理员第一次使用设备命令或 `/小爱 检查` 时登记接收人。定时检查依赖 XiaoQing 进程持续运行。

## 配置文件与终端入口

默认配置位于项目根目录 `data/xiaoai/`：`token.json` 保存登录和服务令牌，`speaker.json` 保存音箱、地区、静默设置和提醒接收人，`auth-state.json` 保存重新授权需求与提醒状态，`requests.json` 保存设备动作重复保护记录。令牌使用明文 JSON，Windows 登录工具为目录设置当前系统用户专用 ACL。

终端入口继续可用：`python -m plugins.xiaoai.setup`。它在终端读取账号、隐藏密码和验证码，密码只存在初始化进程内存中。可使用 `--region de|i2|ru|sg|us`、`--audible`、`--data-dir <实际插件数据目录>`。运行小青和执行终端初始化应使用同一系统用户；初始化宜在插件空闲时执行。默认请求静默执行，实际播报效果取决于音箱固件。

## 设备能力与调用

Agent 使用 `xiaoai_devices`、`xiaoai_capabilities`、`xiaoai_execute` 读取设备和接口并提交结构化计划。底层通过 `/米家 数据`、`/米家 接口`、`/米家 调用` 复用命令权限与执行器，全程跳过小爱插件的模型解析。结构化调用可携带 `original_request`，Agent 自动传入任务用户原话，用于核对出粮数量；设备份数仍由执行器换算。普通用户发送自然语言时继续使用插件自己的解析模型。

自然语言与结构化计划统一在执行入口完成整份校验和原话数量核对，通过后再写入防重复记录并提交。单次计划复用每台设备的能力副本，持久规格保持原样。音箱转发与设备操作共享防重复规则，分别保存各自的请求记录。

- `/米家 设备` 列出当前账号设备；`/米家 刷新设备` 更新规格缓存。
- `/米家 能力 <设备名称>` 一次展示全部功能，按可执行、可设置、可查询和设备事件分组。可使用唯一匹配的名称片段；直接发送完整设备名也能查看功能。
- `/米家 家里温湿度多少`、`/米家 台灯亮度调最高`、`/米家 关灯泡，开台灯` 使用自然语言规划。
- `/米家 份量 10`（单台喂食器）或 `/米家 份量 <设备名> 10` 设置设备每份估算为 10 克；`/米家 出一份粮` 使用该设置。
- `/米家 天气城市 北京` 设置默认城市；`/米家 天气` 或 `/米家 北京未来三天天气` 查询天气。
- `/米家 调用 {"operations":[{"device":"设备编号","capability":"p2.1","op":"read"}]}` 提供结构化调用；设置使用 `op="set"` 和 `value`，动作使用 `op="action"` 和 `args` 数组。
- `/小爱 执行 <原话>` 保留音箱语义转发。入口别名为 `/小爱`、`/xiaoai`、`/米家`。

自然语言解析使用 `plugins.xiaoai.ai.routes.plan`。先选择最多四台设备，再根据实际能力生成最多十二步计划。所有步骤通过类型、范围、枚举、权限和参数校验后开始执行。模糊份量需要先配置克数。设备名重复时使用编号。云端未公开的能力需要单独适配。

红外灯泡提供开关。红外空调提供开关、模式、温度及风速增减；绝对风速与扫风通过绑定音箱的静默语义动作转发，反馈标记为待确认。红外设备的物理状态需要现场核对。

`capabilities.json` 保存账号、地区隔离的规格缓存，每次请求重新确认设备成员；`preferences.json` 保存默认城市和设备份量；`device-requests.json` 保存直接调用的重复保护记录。相同消息身份保护 24 小时，相同操作保护 20 秒。设备变更提交一次，超时保留记录。可读属性在设置后回读；不匹配时停止后续步骤。动作成功响应表示云端接受，设备执行效果按实际反馈确认。

默认自然语言请求使用设备接口和天气接口。显式音箱转发提交后尝试读取新应答，缺少匹配记录时返回已提交、待确认。规格、设备固件和云服务影响兼容性。

参考：[MiService](https://github.com/Yonsm/MiService)、[MIoT 规格](https://home.miot-spec.com/)、[米家扫码登录协议参考](https://github.com/Do1e/mijia-api/blob/main/mijiaAPI/apis.py)。

设备列表和单设备功能清单一次完整展示，使用图标与分组区分在线状态、操作与查询。规格中的常见英文枚举转换为中文；含义缺失的选项明确标注待确认。`小爱 接口 <设备名> [页码]` 提供完整结构化规格。

## 数据与部署

账号凭据保存在本机 `data/xiaoai/`，该目录受 Git 忽略规则保护。自然语言解析向已配置的模型服务发送本次指令、设备名称、房间、型号、在线状态、派生设备编号及相关能力；登录令牌留在小米认证与设备接口链路。天气查询向 Open-Meteo 发送城市名称及对应坐标。直接使用设备、能力和结构化调用命令时由插件本地解析。

新增模型路由需要修改 `config/config.json`。运行中的配置监视器可能因外部配置变更撤销凭据并关闭 QQ 连接。部署时应安排从主机侧重启小青，让配置与凭据一起加载；QQ 通道断开后需通过主机侧恢复。

## 喂食器单位

`xiaomi.feeder.pi2001` 的出粮动作按整份执行。插件接受克数作为请求参数，在执行边界按已设置的每份估算克数换算设备份数；回复同时列出提交份数和估算克数。按每份约 10 克设置时，10 克请求提交 1 份，20 克提交 2 份；5 克、15 克等无法整除的请求在任何设备动作前拦截。自然语言计划还会核对原话中的数量，自动取整或改量会被拦截。缺少每份估算值时出粮保持阻止。

该型号旧规格中的“克数”标签与当前固件行为有差异。设定出粮量属性保持只读，喂食计划写入及更新动作待完成独立协议核验后启用。每份实际重量取决于粮食，`份量` 设置用于估算。[小米官方说明](https://www.mi.com/ph/support/faq/details/KA-243397/)。

功能页优先展示可直接发送的中文例句。台灯按开关、亮度、灯光冷暖和模式组织，同一功能的多个底层接口合并展示。完整参数通过“接口”命令查看。

当前设备的空调、净化器、摄像机、投影仪、音箱、饭盆、水盆、电饭煲、路由器、手环和温湿度计均展示对应日常任务的例句。例句按当前能力及访问权限筛选。充电器说明当前接入的恢复默认设置功能；电饭煲的长篇调试字段在普通功能页使用简短名称，原始说明保留在接口页。
