# 🏠 米家设备与小爱桥接

`xiaoai` 自动发现已登录账号下的米家设备，按型号整理 MIoT 属性、动作和事件。Bot 管理员在私聊里用自然语言查询和控制设备，小青 Agent 通过命令目录代为执行。温湿度直接读取传感器，天气使用 Open-Meteo。设备调用走小米云端，Bot 与设备不必在同一个网络。

---

## 🔐 使用条件

- 命令只给 Bot 管理员，只在私聊里用。入口为 `/米家`，别名 `/小爱`、`/xiaoai`。
- 在实际运行 XiaoQing 的 Python 环境、项目根目录安装依赖，再由管理员 `/reload` 加载插件：

  ```bash
  python -m pip install -e ".[xiaoai]"
  ```

  未安装依赖时插件仍会加载，使用时提示先安装依赖。

- 自然语言入口需要在 `config/config.json` 配置 `plugins.xiaoai.ai.routes.plan`。设备、能力和结构化调用这几条命令由插件本地解析，不需要模型。
- 修改 `config/config.json` 后怎么生效，见[配置详解的生效矩阵](../../docs/06-configuration.md#生效矩阵)。

## ⌨️ 命令

| 命令 | 说明 |
| --- | --- |
| `/米家 <原话>` | 自然语言查询和控制，例如 `/米家 家里温湿度多少`、`/米家 台灯亮度调最高`、`/米家 关灯泡，开台灯`、`/米家 北京未来三天天气` |
| `/米家 设备` | 列出当前账号的设备名称和在线状态，设备重名时同时显示编号 |
| `/米家 刷新设备` | 重新发现设备并更新规格缓存 |
| `/米家 能力 [设备名或编号]` | 一次展示一台设备的全部功能，按可执行、可设置、可查询和设备事件分组；可以用唯一匹配的名称片段，直接发送完整设备名也能查看 |
| `/米家 接口 <设备名或编号> [页码]` | 完整的结构化规格，每页 6 项；也接受 `{"device": "d1", "page": 2}` |
| `/米家 数据` | 设备清单的结构化 JSON |
| `/米家 调用 <JSON>` | 直接执行 1–12 项操作，例如 `{"operations":[{"device":"设备编号","capability":"p2.1","op":"read"}]}`；设置用 `op="set"` 和 `value`，动作用 `op="action"` 和 `args` 数组 |
| `/米家 天气 [城市]`、`/米家 天气城市 <城市>` | 查询天气；保存默认城市后可以省略城市 |
| `/米家 份量 [设备名或编号] <克数>` | 设置喂食器每份的估算克数；只有一台喂食器时可以省略设备 |
| `/米家 登录 [地区]`、`选择 <序号>`、`取消登录` | 扫码授权并绑定音箱，见下文 |
| `/米家 续期`、`状态`、`检查` | 立即更新服务令牌；查看本地授权和登录进度；检查云端授权和音箱连接 |
| `/米家 执行 <原话>` | 把原话交给已绑定的小爱音箱，返回音箱应答或提交状态 |
| `/米家 设置`、`/米家 帮助` | 已保存的偏好和高级操作说明；常用入口 |

设备列表和功能清单一次完整展示，用图标和分组区分在线状态、操作与查询。规格里常见的英文枚举转换成中文，含义缺失的选项标注待确认。功能页优先给出可以直接发送的中文例句，例句按设备的实际能力和访问权限筛选；同一功能的多个底层接口合并展示（台灯按开关、亮度、灯光冷暖和模式组织），冗长的调试字段在功能页用简短名称，原始说明留在 `接口` 页。

指令长度：`/米家 调用 <JSON>` 最多 6000 字，其余指令（包括自然语言原话）最多 300 字。账号下设备数上限为 500 台。

## 🔑 登录与续期

### 扫码登录

管理员私聊发送 `/小爱 登录`，小青单独私聊发来二维码。用米家 App 扫码并确认，二维码最长有效 5 分钟。扫码成功后小青列出音箱，发送 `/小爱 选择 1` 完成绑定，选择阶段同样有效 5 分钟。

- `/小爱 状态` 查看当前进度和音箱列表，`/小爱 取消登录` 取消本次流程。选择和取消只有登录发起人可以操作。
- 同一时间只有一个扫码会话；重新发送登录命令会替换自己上一次的流程。
- 初次登录默认使用中国大陆地区，`/小爱 登录 de` 这样可以指定地区，支持 `cn`、`de`、`i2`、`ru`、`sg`、`us`。已有配置沿用原来的地区和静默设置。
- 登录通过米家 DID 关联音箱，按设备型号查询 MIoT 规格，自动选择 `execute-text-directive` 动作和参数顺序。扫码和绑定只做登录与只读发现。
- 二维码在内存中生成，经敏感消息通道投递；登录链接和待绑定令牌只留在内存里，选择完成后才保存正式配置。二维码过期、选择超时、取消、插件卸载或进程退出都会结束当前流程，已保存的配置不受影响。

### 终端入口

`python -m plugins.xiaoai.setup` 在终端读取账号、密码（隐藏输入）和验证码，密码只存在初始化进程的内存里。可用参数：`--region cn|de|i2|ru|sg|us`（默认 `cn`）、`--audible`、`--data-dir <实际插件数据目录>`（默认 `./data/xiaoai`，所以要在项目根目录运行，或显式指定）。运行小青和执行终端初始化要用同一个系统用户，初始化宜在插件空闲时进行。请求默认静默执行，实际是否播报取决于音箱固件。

### 自动续期与失效提醒

- 插件每 30 分钟检查一次米家和小爱服务的访问状态；这项检查依赖 XiaoQing 进程持续运行。
- 服务令牌距上次获取满 6 小时后，用已有的 `passToken` 自动换取新令牌并保存；执行命令前也会检查令牌年龄。6 小时是主动续期的策略，实际有效期由小米服务决定。`/小爱 续期` 可立即手动更新；`passToken` 失效或需要额外验证时使用 `/小爱 登录`。
- 遇到明确的服务授权错误时尝试一次续期。只读查询在续期后重试一次；设备动作不重试，提示先核对设备实际状态。
- 续期成功后接口仍拒绝访问时，保留登录状态并提示稍后检查。网络故障和临时的服务错误保留原凭据，等下一次检查。
- 小米要求重新授权时，小青私聊提醒绑定人发送 `/小爱 登录`。提醒发送成功后记为已通知，发送失败时在后续检查里重试；每一轮失效单独记录。
- 通过消息绑定的人自动成为提醒接收人。用终端入口初始化的配置，在管理员第一次使用 `/小爱 执行` 或 `/小爱 检查` 时登记接收人。

## 🔄 设备调用

自然语言根据实际能力生成至多四台设备、十二步操作的计划；规格预载齐全时一轮完成，其他情况先选择设备再生成计划。所有步骤通过类型、范围、枚举、权限和参数校验后才开始执行。设备名重复时使用编号；云端没有公开的能力需要单独适配。

- 自然语言和结构化计划在同一个执行入口完成整份校验和原话数量核对，通过后写入防重复记录并提交。相同消息保护 24 小时，相同操作保护 20 秒；音箱转发和设备操作用同一套规则，各自保存请求记录，每份记录最多保留 1000 条。
- 设备变更只提交一次，超时时保留记录。可读属性在设置后回读，对不上就停止后续步骤。动作的成功响应只表示云端已接受，设备的实际效果以反馈为准。
- 红外灯泡提供开关。红外空调提供开关、模式、温度和风速增减；绝对风速和扫风通过绑定音箱的静默语义动作转发，反馈标记为待确认。红外设备的物理状态需要现场核对。
- `/米家 执行` 提交后尝试读取音箱的新应答，没有匹配的记录时回复“指令已提交给小爱”，并说明设备执行结果待确认。规格、设备固件和云服务都会影响兼容性。

小青 Agent 代为执行时把发起人的原话写在 `/米家` 后面，和本人直接发送一样由插件的规划模型选择设备、生成并校验操作；Agent 不读取设备接口，也不自己拼操作计划。自然语言入口在命令目录里声明为写入：结果由 Agent 按人设交代，同一任务里完全相同的指令不重复执行。`/米家 数据`、`/米家 接口`、`/米家 调用` 留给需要精确接口的手动调用。

规划时会按请求中的设备名称预载能力，最多 4 台、12,000 字符；小型目录也可整体预载。模型始终看到完整设备目录，目标规格齐全时一轮生成计划；需要其他设备或规格较多时先选全目标，再取得规格生成计划。设备权限、参数、出粮数量和重复保护继续由执行器统一校验。

可读写属性提交前先读一次当前值作为基准（最多 2 秒，读不到不影响提交）。设置成功后立即读取状态，最多读取 5 次，相邻读取等待 0.5、1、1.5、2 秒，整个确认阶段最多 6 秒。确认核对设备、属性和目标值，新旧以云端自己的回报判断：基准已是目标值时一读即确认“提交前已是目标状态”，后续操作照常进行；基准不同而回报到达目标，说明回报已更新。只有读不到基准时才比对回报时间，按本机与云端最多相差 5 秒的时钟容差判断，早于提交或缺失、异常的时间戳保留“待确认”。确认阶段的回报需符合规格；普通查询照实显示云端回报，浮点上报的尾差按规格步长对齐。确认超时、读取失败或目标未达到时停止后续操作，设备写入始终只提交一次。纯动作、仅写属性及红外控制保留提交回执和各自的确认限制。

### 喂食器

`xiaomi.feeder.pi2001` 的出粮动作按整份执行。插件接受克数作为请求参数，在执行时按已设置的每份估算克数换算成设备份数，回复同时列出提交的份数和估算克数。

- 每份约 10 克时，10 克提交 1 份，20 克提交 2 份；5 克、15 克这类除不尽的请求在任何设备动作之前被拦截。
- 没有设置每份估算值时不出粮；说“出一份粮”这类模糊份量前要先用 `/米家 份量` 设置克数。
- 单次请求上限 150 克，`/米家 份量` 设置的每份估算克数同样限 1～150。
- `/米家 执行` 的原话里带出粮、投喂、喂食等字样时会被拦截，出粮请直接用自然语言，如 `/米家 出一份粮`，由插件按整份与数量校验后执行。
- 自然语言计划会核对原话里的数量，自动取整或改量会被拦截。核对用的原话是 `/米家` 后面的文字，Agent 代为执行时写的就是发起人的原话。`/米家 调用` 若由 Core 的命令执行器代为运行，则按其传入的发起人原话核对，补充的要求按先后附在后面，以最后一次明确说出的数量为准。直接发送的 `/米家 调用` 没有可核对的原话，不做数量核对，设备份数仍由执行器换算。
- 这个型号规格里标为“克数”的参数实际按份执行。设定出粮量的属性只读，喂食计划的写入和更新动作没有开放。每份的实际重量取决于粮食，`份量` 只用于估算，见[小米官方说明](https://www.mi.com/ph/support/faq/details/KA-243397/)。

## 💾 数据与隐私

数据位于 `data/xiaoai/`，这个目录不进 Git：

| 文件 | 内容 |
| --- | --- |
| `token.json` | 登录和服务令牌（明文 JSON；目录只允许当前系统用户访问） |
| `speaker.json` | 音箱、地区、静默设置和提醒接收人 |
| `auth-state.json` | 重新授权需求与提醒状态 |
| `capabilities.json` | 按账号和地区隔离的规格缓存，一天内复用，`刷新设备` 强制更新；每次请求重新确认设备成员 |
| `preferences.json` | 默认城市和设备份量 |
| `requests.json`、`device-requests.json` | 音箱转发、设备动作各自的防重复记录 |

自然语言解析向已配置的模型服务发送本次指令，以及设备名称、房间、型号、在线状态、派生的设备编号和相关能力，以及已保存的默认天气城市和每份估算克数；登录令牌只在小米认证和设备接口之间使用。天气查询向 Open-Meteo 发送城市名称和对应坐标。

## 🩺 排障

| 现象 | 处理 |
| --- | --- |
| 提示小米登录已失效，或账号与绑定信息需要更新 | 私聊发送 `/小爱 登录` 重新扫码；只是服务令牌过期时 `/小爱 续期` 即可 |
| 提示自然语言解析需要配置，或暂未完成 | 检查 `plugins.xiaoai.ai.routes.plan` 和对应模型的凭据；这期间 `设备`、`能力`、`调用` 照常可用 |
| 提示设备尚未确定，或设备规格较多 | 在原话里写明设备名称，一次只对一两台设备提要求；名称重复时用 `/米家 设备` 返回的编号 |
| 出粮被拦截 | 用 `/米家 份量` 设置每份克数；请求的克数要能被每份克数整除且不超过 150；有多台喂食器时指定设备；不要用 `/米家 执行` 出粮，直接说“出一份粮” |
| 天气城市找不到或有多个同名地点 | 使用城市全名或英文名称，必要时补充省份或国家 |
| 提示绑定的小爱音箱离线 | 检查音箱的网络；`/米家 执行` 和红外空调的风速、扫风依赖它 |
| 音箱转发提示“提交结果待确认”，或“指令已提交给小爱”而没有应答 | 以音箱的实际播报或设备状态为准 |
| 提示“已被重复保护拦截” | 先核对上次执行结果；相同操作需间隔 20 秒，同一条消息 24 小时内不会重复执行 |
| 提示“设备动作记录已达上限” | 稍后再试；防重复记录最多 1000 条，24 小时后逐条过期 |
| 提示“小米云拒绝了当前客户端（错误码 -127）” | 更新米家接口适配；设备请求与登录请求共用客户端标识，修改位置为 `client.py` 的 `MIHOME_USER_AGENT` |
| 提示“米家云端暂时限流” | 暂停重复请求，稍后再试；持续失败时检查 `cloud.request.rejected` 的 `http_status`、`upstream_code` 和 `reason_code` |
| 提示“上一条小爱请求正在处理” | 等上一条完成再发；单条请求最长处理 120 秒 |
| 提示“请私聊发送 /小爱 登录，用米家 App 扫码完成授权” | 尚未登录或本地授权文件缺失，按“登录与续期”完成扫码登录 |

后台授权检查每半小时执行一次。失败通过现有脱敏日志系统记录 `cloud.health.failed`，恢复后记录 `cloud.health.recovered`。云端拒绝日志保留数值状态码和固定原因分类；凭据、设备清单及原始错误正文保持私密。设备动作保持单次提交。

扫码等待、规格发现、自然语言规划、音箱提交和应答、设备操作及提交后的状态读取也分别记录失败事件。动作提交超时保持“结果待确认”，后续操作停止；日志保留异常类型和代码位置。

`device.discovery.completed`、`plan.model.completed`、`device.operation.submitted`、`request.completed` 分别记录发现、各轮规划、提交和请求总耗时。`device.confirmation.observed` 记录读取次数、回报年龄和分类，`device.confirmation.completed` 记录确认耗时及最终原因：`matched`、`already_target`、`stale_report`、`timestamp_unverified`、`value_mismatch`、`timeout` 或 `read_failed`。基准读不到记录 `device.baseline.unavailable`，取消记录 `device.confirmation.cancelled`；纯动作、仅写属性和红外边界记录 `device.confirmation.unavailable`。日志包含阶段和数值诊断字段，设备名称、属性值及原始响应保持私密。
