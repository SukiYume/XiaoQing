# Twitter 图片插件

从指定 X/Twitter 账号抓取图片到有限的本地缓存，并随机发送一张本轮尚未发送的图片。

## 命令

| 命令 | 别名 | 权限 | 行为 |
|------|------|------|------|
| `/twimg` | `/twitter`、`/推特` | 所有人 | 只读取本地缓存，随机发送一张图片 |
| `/tw_fetch` | `/抓取推特` | 管理员 | 提交后台抓取，立即返回并在完成后通知 |

每天 `03:00` 还会启动一次静默后台抓取；定时回调会立即返回，只更新缓存，不主动向群聊发消息。

## 配置

在 `config/secrets.json` 中配置：

```json
{
  "plugins": {
    "twitter": {
      "user_id": "Twitter用户ID",
      "headers": {
        "authorization": "Bearer <TWITTER_BEARER_TOKEN>"
      },
      "cookies": {},
      "proxy": "http://proxy.example.com:8080",
      "max_pages": 50
    }
  }
}
```

- `user_id`：目标用户 ID，可使用非空字符串或正整数；缺省时沿用兼容默认值。
- `headers`：API 自定义请求头，只接受有限的字符串键值；认证信息没有代码内默认值。
- `cookies`：API Cookie，只接受有限的字符串键值。
- `proxy`：可选的 `http://` 或 `https://` 代理；空值和非法地址都视为未配置。
- `max_pages`：单次最多检查的页数，只接受整数并限制在 `1..50`；其他类型使用默认值 `50`。

不要把真实认证头或 Cookie 提交到仓库。公共媒体下载不会携带 API 自定义头、Cookie 或代理配置，避免凭据被重定向到媒体端点。

## 下载与缓存边界

- API 响应最多 `5 MiB`，并限制 JSON 深度、节点数和字符串长度。
- 只下载 `pbs.twimg.com`、`ton.twitter.com`、`video.twimg.com` 的 HTTPS 媒体。
- 单张图片最多 `10 MiB`、`4000 万`像素和 `120` 帧，只接收 JPEG、PNG、WebP。
- 单轮最多新增 `100` 张图片，同时最多下载 `4` 张；手动命令和定时任务共用同一后台抓取，重复请求不会再排队执行一轮。
- 图片以内容 SHA-256 命名。缓存最多 `5000` 项、`512 MiB`，文件保留期为 `90` 天。

运行数据位于插件数据目录：`images/` 保存缓存图片，`posted.txt` 保存当前发送轮次。发送状态读取上限为 `1 MiB`，陈旧文件名会自动剔除；全部图片发送一轮后会重置状态。

## 注意事项

- `/twimg` 不会临时联网；缓存为空时需等待定时任务或由管理员执行 `/tw_fetch`。
- `/tw_fetch` 只负责提交后台任务，不占用命令回调等待整轮分页；抓取成功或失败都会向发起命令的会话发送一次结果。
- 插件依赖目标站点当前可用的 GraphQL 接口和显式认证配置，站点接口变化可能导致抓取暂时失效。
- 插件不再默认使用本地 `127.0.0.1:1080` 代理，只有显式提供合法代理时才启用。
