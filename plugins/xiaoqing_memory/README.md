# 🧠 XiaoQing Memory

XiaoQing Memory 是小青的统一记忆。聊天（`xiaoqing_chat`）、办事（`xiaoqing_agent`）和网上生活（`xiaoqing_life`）经同一套接口把原始记录写进来，每晚整理成关于每个人、每个群和她自己的几页“了解”，每一轮说话前再按预算取出相关的几行。

同一个人在群里说过的事、私聊里托付的事、帮他办过的事，她都按场景分开记得：私聊里的事不进群，一个群的事不进另一个群；他在群里公开说过的自己的事，可以带进和他本人的私聊。

本插件不直接说话。关闭或不在时，三个插件照常工作，只是没有长期记忆。

---

## ✨ 记什么

| 层 | 内容 | 谁写、什么时候 |
|---|---|---|
| 事件 | 只追加的原始记录：每条聊天消息（群友的、她自己的、其他插件以她身份发的）、每次办事的经过 | 聊天在消息落盘后推送；agent 在任务结束时写一条 |
| 笔记 | 一条原子记忆：关于某个人的事、办事偏好、群里的事、她说过的近况和承诺和往事、群友到期的话头、她的网上经历和日记。每条带范围、来源和出处 | 夜间整理；聊天在回复投递后抽取；life 在定时检查时发布 |
| 页面 | 关于一个对象（某个人、某个群、她自己）的整理结果，每行引用笔记，有字数上限 | 夜间整理 |
| 常驻块 | 每轮注入提示词的那一小段，从页面和笔记里按预算取 | 每轮取用，不调模型 |

人物页分“稳定的事 / 最近在忙 / 和你之间 / 办事 / 别主动提”五节（≤600 字），群页分“这个群 / 常聊的 / 群里的梗 / 最近的事”（≤800 字），自我页分“最近在做的 / 这阵子的兴趣 / 讲过的往事”（≤800 字）。每行用她自己的话写，只有梗和称呼照群里的原话写进引号（“群里的梗”、人物页“和你之间”的梗），换个说法就接不上了。

### 取用

| 场景 | 给什么 |
|---|---|
| 聊天回复（`purpose=reply`，走规划器的轮次在规划前取，规划器也看说话人页面和群页） | 她的自我页和仍然有效的近况、打算、承诺、往事；说话人的页面；群页；和这句话字面相关的旧事（含还没整理的原始记录，以及话里点名的群友的页面）；说话人到期可以顺口问的话头；群聊里另给这两三天可以自然提起的话题词（只有词，聊天转交给 xiaoqing_life 当上网的方向） |
| 主动开口（`proactive`） | 她的近况和自我页、群页；群聊里另给这个群还记着的全部可以自然提起的话题词（聊天转交给 xiaoqing_life，用来认出哪些事是这个群聊到她才去搜的）；私聊时这个朋友的页面和到期话头 |
| 开新办事会话（`task`） | 发起人的页面（办事偏好排在最前）和在这里答应过他还没办完的事；来源链里有网页文字的内容一律不给 |

预算：自我 800 字（页面占一半）、说话人 500、群 300、相关旧事 500，整行取舍。她最近几条回复里说过的内容不再给；标为“别主动提”的行带“对方没提就别主动说”，可信度低的带“拿不准”。时间上的标注按事情说出（或被再次印证）的时间算，被取用不算：写着日子的事（行程、活动、截止、约好的时间）过了那天带“写着的日子已经过了”；180 天没被说起也没被印证的带“很久以前的事”；“最近在忙”“最近在做的”里两周前说的事带“约 N 天前的事”。私聊里读到的这个人在群里的页面，每行带“在群里说的”：原话里“在群里”这类范围到了私聊不能当成一样。认人看 QQ 号：说话人现在的称呼和记得的称呼不一样时（改了群名片），抬头注明“同一个人，也叫……”。迁移来的旧话题摘要只在对方明确回指以前的事（“还记得”“上次”“之前”……）时出现。页面没引用的笔记只在页面上次重写之后才记下时列为“刚记下”；重写时就有却没写进页面的，是写页面时判断重复或不值得写的（迁移来的旧事实常有好几条说同一件事），不单独列出。“多久以前说的”“多久以前答应的”一律按原话说出的时间算，迁移和夜间整理晚写入的不当成刚说的。

自我页另按行给出（`self_lines`），每行带上它引用的网上生活条目在 xiaoqing_life 里的键、是不是只引用了网上生活条目。聊天先向 life 取这一轮的网上生活，life 交出细节的条目也带着同样的键（`shown_keys`），自我页一行常概括好几条经历，只要其中一条这一轮给了细节，聊天这一轮就不放这一行：同一件事不一详一略说两遍，细节以 life 给的为准；另有依据的行（比如她在聊天里说过的）和一句话简介照常保留。

### 夜间整理

定时检查每 30 分钟一次。一个范围在夜间窗口里（默认 02:00–05:00）且有新事件，或者积压的新事件达到 `backlog_trigger_events` 时整理：

1. **写笔记**：水位之后的事件按批交给模型，写出新笔记、再次印证的旧笔记和说法变了的旧笔记；一批里没有人说的话（只有她自己的消息和其他插件的推送）时不调模型，水位照样前移。模型的输出读不出 JSON 对象时这一批不算整理过，水位不动，下次再试；同一批连着三次都读不出来才放过，后面的消息不会被它挡住（空对象是“这一批没有要记的”，照常前移）。事件行带日期和星期，提示词给出今天的日期，笔记里的时间写成具体日期；过了某一天就不再是眼下的事（行程、活动、截止、约好的时间）时笔记记下那一天，过了那天再留 30 天后结束。办事偏好只记以后办事还用得上的固定习惯、默认做法、纠正过她的地方和踩过的坑，某一次办了什么由办事记录留着；办事时知道的关于这个人的事照常记成关于他的事。群聊里顺带写下这段群友在聊的话题词（话题 ≤12 字、关键词 ≤8 字，带用法标签，出处必须是群友自己的消息，其他插件推送的内容不算），记在范围状态里，留 14 天、最多 20 个。每条引用事件编号并附逐字摘录，本地核对摘录确实出现在那条原文里；关于某个人的事必须出自他本人的话或替他办的事。和已有笔记说同一件事时只更新印证时间；住址、学校、工作这类同一时间只有一个答案的属性，新说法替换旧说法。
2. **并页面**：有新笔记的对象，以及页面上写着的日子在上次重写之后过了的对象，重写页面，每行引用笔记 ID；提示词给出今天的日期，过了日子的事改成已经发生的说法或删掉，笔记里的条件和范围照写。引用不存在、越界或超出字数时整页作废，保留旧页面。没有模型预算或调用失败时，新笔记按确定性规则追加到页面的“最近”一节，等下一次重写时再合并；没有新事件的范围在夜间窗口里每天也重写一次待重写的页面，上线当天追加进来的旧数据不用等到那里再有人说话。
3. **对照原文核对**：每晚抽几行还有没核对过的依据的行（取用多的、可信度低的、最久没核对的优先），连同引用的原文和原话前面的几条聊天（都带日期和星期，笔记里换算出来的具体日期才核对得了）交给模型判断。原文支持的，依据记为核对过；部分支持的，行改成按原文改好的说法，只依据一条笔记时笔记也改掉，下次重写不会写回去；不支持的，删掉这一行，撤回还没核对过的依据。依据都核对过的行不再核对，核对过的笔记不会因为后来的一次判断被撤回。迁移来的旧数据、网上经历和工具记下的办事记录不参加。
4. **清理**：到期的笔记结束，结束超过保留期的删除；每个对象每一类的有效笔记数有上限（人物的事实、偏好、话头算一类，办事记录另算）；事件按保留期删整月文件。

每天的模型调用有上限（`max_llm_calls_per_day`），先占预算并落盘再调用，失败不退还。几个范围都要整理时，群友说的话多的先整理，只有推送的排最后。整理开始时记下范围的代际，期间被清空则放弃。

## 🔐 范围和来源

| 范围 | 含义 |
|---|---|
| `global` | 关于她自己和她学到的东西，哪里都可见 |
| `g<群号>` | 这个群里说的事，只在这个群可见 |
| `u<QQ号>` | 和这个人的私聊，只在这个私聊可见 |

可见性只有一个函数（`scopes.py` 的 `note_visible` / `event_visible`）：`global` 都可见；同范围可见；读取方在 `u<X>` 时，某个群里关于 X 本人、出自 X 原话的人物笔记可见；其余不可见。页面按行过滤，一行引用的笔记全部可见才显示。

调用方名字和用户主体所在的范围由 Core 写进载荷，调用方填的同名字段无效；用户主体发起的调用，作用范围必须等于主体所在的会话。各调用方能写的类型固定：chat 写聊天消息和她自己的近况、承诺、往事与群友的话头，agent 只写办事经过，life 只写网上经历、日记和查明白的事（一律在 `global`）。

来源记为群友原话、她自己说的、网页文字、工具输出、管理员或整理产出。整理写的页面、她自己的回复和日记不能给一条事实增加可信度；来源链里有网页文字的内容不会交给有命令执行能力的 agent。

## ⚙️ 开启

插件默认开启。在 `config/config.json` 里给整理配置 `reasoning` 路由（缺失时只记录、取用，不整理）：

```json
"xiaoqing_memory": {
  "enabled": true,
  "ai": {"routes": {"reasoning": ["gpt-terra", "deepseek-flash"]}}
}
```

`xiaoqing_chat`、`xiaoqing_agent`、`xiaoqing_life` 的 `plugin.json` 已在 `uses_services` 里声明各自用到的 `memory.*` 服务。

### 配置字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `true` | 总开关。关闭时服务返回 `None`，定时检查不整理 |
| `event_keep_days` | `365` | 原始记录保留多少天（按整月删） |
| `night_start` / `night_end` | `"02:00"` / `"05:00"` | 夜间整理窗口（配置时区） |
| `backlog_trigger_events` | `150` | 积压这么多新事件时窗口外也整理 |
| `max_llm_calls_per_day` | `16` | 每天整理用的模型调用上限 |
| `max_page_rewrites` | `6` | 一次定时整理最多重写几份页面 |
| `verify_calls_per_night` | `2` | 每晚核对用几次模型调用（每次 4 行） |
| `batch_chars` | `6000` | 写笔记时每批事件的字数 |
| `self_budget` / `speaker_budget` / `group_budget` / `hits_budget` | `800` / `500` / `300` / `500` | 常驻块各段的字数预算 |
| `max_notes_per_subject` | `40` | 每个对象每一类最多保留的有效笔记（人物的事实、偏好、话头算一类，办事记录另算） |
| `stale_days` | `180` | 多久没被说起也没被印证算“很久以前的事” |
| `superseded_keep_days` | `90` | 结束、被替换、撤回的笔记再留多久 |
| `legacy_keep_days` | `180` | 迁移来的旧话题摘要留多久 |
| `task_note_days` | `90` | 办事记录留多久 |

`reasoning` 路由的调用参数（温度、超时、重试）在 `config.py` 里用 `declare_route_defaults` 声明。

## 🔧 命令

`/mem` 只给 Bot 管理员，只在私聊里用。

| 子命令 | 说明 |
|---|---|
| `/mem status` | 各范围的事件、笔记、页面数量，整理水位和待整理条数，今天用了几次模型 |
| `/mem stats` | 最近 7 天的计数（写入、取用、整理、核对、清理） |
| `/mem page <范围> [QQ号\|group\|self]` | 看页面列表或一份页面，每行带引用的笔记 ID |
| `/mem search <范围> <关键词>` | 在一个范围里查笔记、页面和原始记录 |
| `/mem why <笔记ID>` | 一条笔记的来源、可信度、摘录和出处原文 |
| `/mem forget <范围> [QQ号\|笔记ID]` | 清空一个范围（代际加一），或删一个人、一条笔记 |
| `/mem consolidate [范围]` | 立刻整理一次，不受每日预算限制；在后台进行，做完私聊发回结果 |
| `/mem rebuild <范围>` | 从笔记重写这个范围的全部页面，做完私聊发回结果 |

普通群友在聊天里用 `/xc 记忆 <关键词>` 查当前会话能看到的记忆。会话重置（`/xc 重置`）同时清空统一记忆里这个会话的内容；这一步没成功时聊天会如实提示，并在之后自动重试。

删掉的内容不会再出现，也不会被写回：

- 页面上照被删笔记写的行和简介一起去掉；清空一个范围时，包括自我页上照它的自我记录写的内容。
- 删除时正在进行的整理稍后才返回：被删的笔记、替换它的新说法和照它写的页面内容都不写。
- 忘掉一个人之后，依据早于那一刻的、关于他的笔记不再写入，包括当时还没整理的旧消息；他之后说的照常记。

## 📁 数据目录

```text
data/xiaoqing_memory/
├── state.json                 # 各范围的下一个编号、代际、整理水位和群里的话题词；每日预算、统计、每晚核对做到哪天
├── events/<范围>/<YYYY-MM>.jsonl
├── notes/<范围>.json
└── pages/<范围>.json
```

事件文件只追加，读取时跳过损坏的行；笔记和页面用 Core 的原子存储写入并保留 `.bak`。

聊天第一次推送某个会话时，把它的旧数据导入：向量库里的人物事实和人物资料（可信度记为旧数据）、话题摘要（只在明确回指时取用，到期删除）、`life/self_timeline.json` 和 `life/open_loops/`。旧文件只读不改；聊天侧在 `memory_outbox.json` 里记下哪些会话已经导入。

## 🧪 测试

```powershell
python -m pytest tests/plugins/xiaoqing_memory tests/core/test_app_memory_capabilities.py -q
```

覆盖范围矩阵、调用方矩阵、事件追加与换月和末行损坏、写入核对、取用的隐私与预算、整理各步的校验与回退、核对撤回、预算与代际、30 天有界增长模拟和 `/mem` 命令。

### 真实验证

- 评测：`python -m scripts.chat_eval run --set memory`（`mem_agent_prefs` 要加 `--driver live`）。剧本预置几天前的对话，整理一次后再问：记不记得、改口后按新的、私聊的事不进群、群里本人说的能带进私聊、伤心事不主动提、分得清谁是谁、办事偏好下次不再问。
- 数据副本回放：`python scripts/run_xiaoqing_memory_consolidate.py --data-dir <数据副本>` 在副本上跑迁移和整理，输出每个范围的笔记数、页面字数和模型调用数，页面另存为 `xiaoqing_memory/pages.txt`。只在副本上运行。
