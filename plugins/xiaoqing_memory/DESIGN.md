# xiaoqing_memory 设计：小青的统一记忆

本文说明这套记忆为什么是现在的样子：目标、原则、数据模型和取舍。模块和数据流见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 0. 目标与边界

目标：

1. 原始记录只追加、可检索，是其上所有内容的核对依据。
2. 关于人、关于群、关于她自己，各只有一份，三个插件经同一套接口读写。
3. 范围和来源各只在一处实现，在读取时强制。
4. 每晚整理一次：从原始记录写笔记、把笔记并成页面、对照原文纠错、清理过期内容。
5. 每轮注入的内容有统一的预算，按优先级整行取舍。
6. 记忆插件不在或关闭时，三个插件照常工作，只是没有长期记忆。

不放进记忆的东西：

- **工作上下文**：聊天的近期 200 条窗口、规划状态、目标、Heartflow；agent 的办事会话。它们是“这一段对话”，不是“记得的事”。
- **运行状态**：life 的规划决策、预算、看过的条目、来源健康度、小课题状态机、兴趣衰减；chat 的频控和主动开口节奏。
- **媒体**：表情库、媒体注册表、梗图。
- **每轮的网上生活取用**：选哪段经历、哪个词条、哪种表达由 `life.turn_context` 按话题和意图挑（它要读的小课题、档案、作品、正在刷什么都只在 life 里，搬过来等于再复制一份）；记忆里的经历、日记、查明白的事进她的自我页，让她“这阵子在干什么”前后一致。两边说到同一条时按 life 的条目键去重，同一件事不一详一略说两遍，细节以 life 为准（机制见 ARCHITECTURE）。
- **黑话和表达**：chat 的黑话挖掘、表达学习和 life 的词条、表达各自保存，各有确认规则（前者是本群自己的梗，后者是网上的流行语，来源和确认方式都不同）。同一个词本群黑话块已经按确认的释义解释过时，life 不再解释一遍（本群只是猜测时照常给 life 查实的意思）；表达提示只在本群没有可用表达时补位。
- **管理员知识库**：留在 chat 的向量库里。

## 1. 原则

1. **事件是底座。** 事件之上的每一层都能从下一层重新生成；改了整理的提示词，可以离线重建后对比。
2. **每条笔记带出处。** 引用事件编号或外部条目 ID，并附逐字摘录；写入前在本地核对摘录确实出现在被引用的原文里。
3. **模型的产出不能当新知识的来源。** 整理写的页面、她自己的回复、日记，都不能给一条事实增加可信度。
4. **范围和来源在读取时强制，只有一处实现。** 调用方是谁由 Core 写入，调用方自己不能声明。
5. **提示词说明记忆是干什么用的，不规定怎么记。** 不写禁用清单，不写“只记某类”的规则；类型的边界靠本地核对守住。
6. **页面必须短。** 整理时合并和删除，每类页面有字数上限。
7. **取用不调模型。** 每轮取用只读内存，回复不因为记忆多等。
8. **每个数字都能从运行记录里看出来。** 每天的计数写进统计并记日志。

## 2. 数据模型

### 范围

范围有 `global`、`g<群号>`、`u<QQ号>` 三种，含义和可见性规则见 README“范围和来源”。范围键和 chat 的会话 ID、agent 的 `ChatRef.key` 相同。

设计上信息只往一个方向流：群里说的、关于他本人的事可以带进和他本人的私聊（他知道自己在群里说过）；反方向一律不行，私聊里的事不进群，一个群的事不进另一个群。

### 来源与可信度

| 来源 | 能否作为事实的依据 |
|---|---|
| `user` 群友或私聊对象的原话 | 只能作为说话人本人的事实依据 |
| `self` 她自己发出的话 | 只能作为她说过什么的依据 |
| `web` 网页文字（life 抓来的，已清洗） | 可以，按 life 的独立来源规则判断查没查实 |
| `tool` 办事经过、其他插件的输出 | 只作为办事经过的依据 |
| `admin` 管理员提供 | 可以 |
| `derived` 整理产出（日记、页面） | 不可以；它引用的笔记才是依据 |

可信度：`stated`（本人原话）、`reported`（别人转述）、`verified`（查实）、`hypothesis`（单一来源）、`legacy`（迁移来的旧数据，没有可核对的原文）。

### 笔记类型

| 类型 | 对象 | 范围 | 谁写 | 本地核对 | 过期 |
|---|---|---|---|---|---|
| `person.fact` | 某个人 | 说的地方 | 整理 | 摘录出自这个人本人的一条消息，或替他办的那件事 | 不过期；写着日子的事过了那天标出，再留 30 天后结束；久了标“很久以前”；受对象上限约束 |
| `person.pref` | 某个人 | 办事的地方 | 整理 | 引用替他办的事或他本人的话 | 被新说法替换；受对象上限约束 |
| `person.loop` | 某个人 | 说的地方 | 回复后抽取 | 当事人最近在这里说过话、时间点合理 | 问过或有结果后结束，再留 7 天 |
| `self.state` / `self.plan` / `self.story` | 她自己 | 只讲她自己时 `global`，涉及对方时原范围 | 回复后抽取 | 出处是她已经发出的话 | 近况 ≤12 小时，打算 ≤48 小时，往事 90–365 天 |
| `self.promise` | 她自己 | 原范围 | 回复后抽取 | 同上 | ≤7 天 |
| `group.fact` | 某个群 | 该群 | 整理 | 摘录出自该群的消息，记下说话人，可信度 `reported` | 受对象上限约束 |
| `work.task` | 发起人 | 办事的地方 | 收到 `task` 事件时 | 事件存在 | 90 天 |
| `episode` / `world.learning` | 她自己 | `global` | life | life 的核对 | life 的保留期 |
| `self.diary` | 她自己 | `global` | life 睡前整理 | 引用经历 | 写入方给的天数（life 给 56 天） |
| `legacy.summary` | 某个群 | 该群 | 迁移 | 无 | 180 天，只在明确回指以前的事时给 |

笔记的 `usage` 由写笔记的模型标注：`normal` 可以自然提起，`tone` 影响和他说话的方式和分寸，`avoid` 对方没提就不主动说。`observed_at` 是最近一次有依据的时间，同一件事再次被印证时更新而不新增。

## 3. 检索为什么不用向量

- 绝大多数取用按对象直达：谁在说话就取谁的页面，在哪个群就取哪个群页，话里点了谁的名就带上谁的页面。
- 剩下的“相关旧事”用相邻两字的字面重合加新近度打分，对中文短句够用，结果可以解释。
- 页面把同一个对象的事聚到一起，比逐条检索更稳；页面短，整页给比挑几条更不容易断章取义。
- 不新增第三方依赖，不接外部服务。

## 4. 整理的提示词怎么写

只说明用途。写笔记的提示词开头：“这份记忆是给以后的你用的：下次和这个人聊天、帮他办事时，哪些事不记下来就会忘，记得就能接得上。聊天记录本身会留着，可以再查，所以不用复述发生了什么。”并页面的提示词开头：“这一页是你对这个人的了解，每次和他说话前都会看一眼，所以要短。同一件事只留一行；说法变了就用新的，旧的留一句‘以前是……’；拿不准的写明拿不准。”每个小节是做什么用的写在提示词里，一行该放哪一节由模型判断。

外部文本和群友原话只放在用户消息的数据里。

调优的办法：拿运行数据的副本在隔离目录里回放，读页面，改提示词里的用途说明，重建后再读；不靠加规则修单个例子。

## 5. 取舍

| 问题 | 选择 | 理由 |
|---|---|---|
| 原始记录留多久 | 365 天，按整月删 | 越久核对越有依据；体积不是问题（每月一个纯文字文件） |
| 群里说的事能否带进私聊 | 能，仅限他本人说的关于他自己的事 | 对方知道自己说过；反方向一律不行 |
| 旧话题摘要 | 导入为只在明确回指时给的旧数据，180 天后删除，不进页面 | 没法核对、重复多；直接删会丢掉以前的印象 |
| 整理的模型与预算 | `reasoning` 路由，每天 16 次 | 离线任务不赶时间，可以用较强的模型；超出时新笔记先确定性追加 |
| 普通群友能否查记忆 | 能，`/xc 记忆` 只查当前会话能看到的 | 和取用的可见性一致 |
| agent 能看到什么 | 发起人的人物页和在这里答应他的事，去掉来源链含网页文字的内容 | agent 有命令执行能力，网页文字不能经记忆进入它的提示 |
| agent 的记忆什么时候取 | 开新办事会话时取一次，存进会话 | 会话内系统提示逐字不变，提示缓存继续命中 |

## 6. 与“记忆的组成”一文的对应

| 文章的结论 | 这里的做法 |
|---|---|
| 分层，离线整理在层间搬运 | 事件、笔记、页面、常驻块；夜间整理 |
| 原始记录是纠错的依据 | 事件只追加并保留；整理第三步对照原文 |
| 好的笔记写明是什么、怎么知道的、哪里拿不准 | 笔记带出处、摘录、可信度 |
| 不加区分地记环境里读得到的状态，效果差 | 不做逐段话题摘要；提示词写明“聊天记录会留着，不用复述” |
| 说明记忆的用途，不规定用法 | 第 4 节的提示词写法 |
| 页面加检索优于单纯检索 | 人物页、群页、自我页；按对象直达 |
| 常驻层必须小，错误会被带进每一轮 | 统一预算；每行有出处；核对 |
| 页面可能比原始材料还大 | 字数上限；整理时合并删除 |
| 整理的产出不一定立刻可用 | 确定性追加；`hits` 扫描还没整理的原始记录 |
| 按取用频率安排核对 | 第三步的抽样优先级；每条笔记核对到通过为止，通过后不再因为一次判断被撤回 |

文章的数据来自 Claude 模型上的任务型基准，这里借的是结构，效果靠评测剧本和数据副本回放验证。
