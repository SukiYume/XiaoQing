# 📅 Pendo

[中文](README.md) | English

Pendo manages personal time and information in XiaoQing. It includes events, tasks, notes, diaries, a ledger, reminders, search, and data transfer. Chat commands support quick records and queries. The Web console supports editing, statistics, and bulk transfer. The Scriptable widget shows summaries on the iPhone home screen.

All Pendo commands operate only in private chat.

## 🚀 Quick start

```text
/pendo
/pendo help event
/pendo event add 明天9点组会，提前30分钟提醒
/pendo todo add 写周报 plan:2030-05-01 cat:工作 p:2
/pendo note add title:会议纪要 content 讨论部署方案 cat:工作 #复盘
/pendo diary add 今天完成了项目复盘 mood:happy score:8
/pendo ledger quick 35.5 午饭 cat:餐饮 account:微信
/pendo search 组会 type=event range=last30d
```

The Manifest also supplies `/日程`, `/待办`, and `/日记` private-chat shortcuts. They forward to `event`, `todo`, and `diary`, respectively.

## 📅 Events

```text
/pendo event add <内容>
/pendo event list [today|tomorrow|week|month|year|YYYY-MM|start..end] [cat:分类] [#标签]
/pendo event view <id>
/pendo event edit <id> <内容>
/pendo event delete <id>
/pendo event reminders [id|范围]
/pendo event reminders list [范围]
/pendo event reminders set <id> <提醒描述>
/pendo event reminders delete <id> <all|today|future|提醒时间>
/pendo event reminders confirm <id> [today|future|all|提醒时间]
```

The aliases for `event` are `e`, `calendar`, `日程`, and `事件`. A single event has one leaf. Repeated events and events with multiple nodes use `event_collections` to organize leaves. A collection ID selects the complete collection. A leaf ID selects an occurrence or one node.

## 📅 Tasks

```text
/pendo todo add
/pendo todo add <内容> [plan:YYYY-MM-DD] [deadline:YYYY-MM-DDTHH:MM] [remind:时间列表] [cat:分类] [p:1-5] [#标签]
/pendo todo list [today|open|done|cancelled|overdue|upcoming|inbox|分类] [open|done|cancelled] [p:1-5] [all|page:n]
/pendo todo view <id>
/pendo todo done <id>
/pendo todo cancel <id>
/pendo todo undone <id>
/pendo todo edit <id> <内容与字段>
/pendo todo delete <id|cat:分类>
```

The aliases for `todo` are `task`, `t`, `待办`, and `任务`. Status values are `open`, `done`, and `cancelled`.

An empty `todo add` starts a short session. The session collects task content, then a planned date. The date input accepts a specific date, `0` for the default, or `无` for no date. Before 20:00 in the user timezone, the default is today. From 20:00, the default is tomorrow. A single-line command or `todo edit` can set deadlines, reminders, categories, priorities, and tags.

```text
/pendo ledger add
/pendo ledger add <金额> <描述> [cat:分类] [in|out|transfer|type:] [account:账户] [to:账户] [merchant:商户] [date:日期] [remark:备注]

/pendo ledger delete <id>
```

The aliases for `ledger` are `bill`, `finance`, `记账`, and `账单`. An empty `ledger add` starts a multi-step session. The user enters the amount and description. The user can select the transaction type, account, and category by number.

`amount_cents` is the primary statistics field. `amount` is its display copy. Transfers use `transaction_type=transfer`.

## ⏰ Search, reminders, and settings

```text
/pendo search <关键词> [#标签|tag=] [type=] [range=] [status=] [category=] [transaction_type=] [account=] [merchant=]
/pendo confirm <id>
/pendo snooze <id> <10m|1h|19:00>
/pendo undo [1..5]
/pendo settings
/pendo settings reminder on|off
/pendo settings timezone Asia/Shanghai
/pendo settings quiet_hours 23:00-07:00
/pendo settings daily_report 08:30
/pendo settings daily_briefing on|off
/pendo settings diary_remind 21:30
/pendo settings ai_consent on|off
```

The aliases for `settings` are `config` and `setting`. Operation snapshots remain available for 5 minutes. `undo` can restrict the query window to 1–5 minutes. `ai_consent` controls permission to send diary text to the configured external AI. Its default is `off`. Local rules remain available.

OneBot sends event and task reminders to the item owner in private chat. Item writes and edits also generate reminder queue rows queried by `fire_at_utc`. Reminder keys use UTC with second precision.

Web event details supply “提前确认” and “重新开启” actions for each reminder. These buttons operate only before the reminder time. Early confirmation stops the first and repeated deliveries. Reopening restores the pending state at the original trigger time.

## 🌐 Web console

### Start and status

```text
/pendo web start
/pendo web status
/pendo web stop
/pendo web token
/pendo web widget-token
/pendo web widget-revoke
```

Runtime parameters are in `config/config.json`:

```json
{
  "plugins": {
    "pendo": {
      "web_enabled": true,
      "web_host": "127.0.0.1",
      "web_port": 12001,
      "web_session_cookie_secure": false,
      "web_demo_enabled": false
    }
  }
}
```

The default address is `http://127.0.0.1:12001`. A TLS reverse proxy and `web_session_cookie_secure: true` are necessary for LAN or public listeners. Demo mode is for controlled local demonstrations.

For a TLS reverse proxy, use this Cookie setting:

```json
{
  "plugins": {
    "pendo": {
      "web_session_cookie_secure": true
    }
  }
}
```

### Login Code and browser sessions

`/pendo web token` returns a single-use login Code. The Code expires after 7 days. Successful exchange creates an HttpOnly Cookie session with a 7-day lifetime. Code and browser session digests stay in the existing `pendo.db`. Valid records remain available after Bot and Web service restarts.

Browser sessions support device lists, individual device revocation, and logout from the current session. The server stores the digest, owner, device identifier, creation time, expiry time, and last-use time.

### Widget Token

`/pendo web widget-token` returns a Bearer JWT with a 365-day lifetime. Its scope is limited to GET requests under `/api/widget/*`. `/pendo web widget-revoke` revokes the current user's valid Widget Tokens. Browser sessions and Widget Tokens both use second precision. They have separate credential types and permission scopes. `PENDO_WEB_TOKEN_SECRET` keeps the Widget JWT signing key stable.

Widget interfaces:

```text
GET /api/widget/summary?section=tasks|ledger|notes|all|auto
GET /api/widget/calendar?start_date=YYYY-MM-DD&end_date=YYYY-MM-DD
Authorization: Bearer <widget_token>
```

The summary interface returns a maximum of 5 recent events. The calendar interface returns all events in an inclusive interval of up to 3660 days. Scriptable looks back at least 30 days. An earlier successful cursor extends this interval to cover the gap.

The script adds, updates, and removes managed events by Pendo item ID. It stores the synchronization cursor in Keychain. It reads the Web address and Widget Token from the top of its source file.

The script is `plugins/pendo/web/scriptable/pendo_widget.js`. See the [Scriptable widget guide](../../docs/pendo-scriptable-widget.en.md) for configuration.

## 📅 Import and export

Chat export creates Markdown archives. OneBot sends them as private-chat file messages:

```text
/pendo export 我的档案
/pendo export 工作回顾 last30d event,todo
/pendo export 账本快照 2026-03 ledger
/pendo export 本月随笔 month note,diary
```

`/pendo import` gives instructions for Web Transfer. Transfer processes `.pendo.zip` Bundles. It supports checks, sample previews, execution, skip, overwrite, copy creation, and operation logs. A Bundle contains a versioned manifest, checksums, and structured data files.

## 💾 Data consistency and recovery

- Full Web edits include the version from the opened form. If another window saves first, the older window gets a conflict. The form keeps input. Reload the item to continue editing.
- Standard users can issue and revoke their own access tokens. Bot administrator permissions are necessary for shared Web service `start` and `stop` commands.
- Events without an explicit timezone use the user setting. Markdown date ranges and time displays use the user timezone. Specific times include the UTC offset. Widget calendar synchronization also keeps offsets. Actual instants stay constant when the phone timezone changes.
- Task deadline changes recalculate relative reminders. Explicit reminder clearing also removes rules. Undoing deletion restores the item and pending queue in one transaction. Sent and confirmed history remains available.
- Ledger entries support three-letter currency codes. Income, expenses, balance, category, and account statistics are grouped by currency. Each currency has separate amounts. Exchange-rate conversion is currently unavailable. Ledger and Stats accept three-letter currency input, with CNY as the default. Dashboard shows CNY trends and summaries for other currencies. Widget details and summaries identify their currency.
- Each `.pendo.zip` data type has a limit of 100,000 records. Five item types plus event collections have a total limit of 600,000 records. Import and export use the same capacity. Each decompressed member is limited to 50 MiB. All decompressed members together are limited to 100 MiB. Uploads are limited to 100 MiB. Unicode text and filenames with Chinese characters or emoji support round trips.

## 💾 Data model

Runtime data is in `data/pendo/pendo.db`.

| Table | Content |
| --- | --- |
| `items` | Event leaves, tasks, notes, diary entries, and ledger entries |
| `event_collections` | Repeated events and events with multiple nodes |
| `reminder_logs` | Reminder queue, delivery leases, and sent and confirmed history |
| `scheduled_delivery_outbox` | Scheduled messages and acknowledgments for each target |
| `operation_logs` | Edit, delete, and undo snapshots |
| `user_settings` | Timezone, quiet hours, briefings, and AI permission |
| `transfer_logs` | Bundle import logs |
| `imported_bundles` | Executed Bundle identities |
| `login_code_registry` | Single-use login Code digests and expiry times |
| `web_session_registry` | Browser session digests, devices, and expiry times |
| `widget_token_registry` | Widget Token identities, expiry times, and revocation states |

All business queries isolate data by `owner_id`, the owning QQ user. The database uses WAL, foreign keys, busy timeout, transactions, and schema migrations. Natural-language event times use the user or event IANA timezone. Timestamps are stored in UTC. Displays convert them to the applicable IANA timezone.

## ⏰ Scheduled tasks

| Manifest ID | Time | Core delivery | Function |
| --- | --- | --- | --- |
| `pendo_reminders` | Each minute | `targeted` private chat | Event and task reminders |
| `pendo_daily_briefing` | Each minute | `targeted` private chat | Check each user's local briefing time |
| `pendo_diary_reminder` | Each minute | `targeted` private chat | Check each user's local diary reminder time |
| `pendo_migrate_todos` | Daily at 00:05 | `targeted` private chat | Move yesterday's open planned tasks forward and notify owners |
| `pendo_prune_operation_logs` | Daily at 00:15 | `silent` | Remove expired operation logs and undo snapshots |
| `pendo_weekly_finance_summary` | Each minute | `targeted` private chat | Financial summary on Sunday at 21:00 in the user timezone |
| `pendo_month_end_finance_summary` | Each minute | `targeted` private chat | Financial summary at 21:00 on the last day in the user timezone |
| `pendo_cleanup_demo_data` | Minute 15 of each 6-hour interval | `silent` | Remove expired Demo data |

Daily briefings, diary reminders, and financial summaries use each user's timezone to determine when they are due. Each task runs once per minute. At the user's local time, it writes the period to `scheduled_delivery_outbox`.

Queued periods hold persistent leases. After process interruption or delivery failure, delivery continues with the original period date. Diary reminders check for a completed diary entry on that date. Claimed event and task reminders also enter a recovery window. Leases prevent concurrent duplicate delivery. Core sends zero messages for silent tasks.

## ⚙️ Dependencies and configuration

Pendo uses these necessary dependencies: `python-dateutil`, `fastapi`, `uvicorn`, `PyJWT`, `pydantic`, and `starlette`. Normal project installation includes these runtime dependencies.

The Web signing secret first uses `PENDO_WEB_TOKEN_SECRET`. If it is absent, Pendo generates and stores a random key in its data directory. Restarts use that same key.

Natural-language parsing and diary analysis use the Core AI model chain at `plugins.pendo.ai.routes.parse`. The distribution configuration is `deepseek-flash → glm-5.2`. The user's `ai_consent` setting controls external diary text analysis.

## 🩺 Troubleshooting

| Symptom | Check or action |
| --- | --- |
| Command shows the module directory | Use `/pendo help <模块>` for full subcommands. |
| Reminder stays pending | Check user settings, default delivery targets, and outbox state. |
| Web startup fails | Check dependencies, port use, listener address, and Cookie security settings. |
| Login Code fails validation | Generate a new Code. Check which Web instance the browser uses. |
| Login page appears again | Check Cookies, `pendo.db` permissions, service clock, and session expiry. |
| Widget returns 401 | Generate a new Token, or check revocation and system time. |
| Bundle import fails | Run checks and sample preview. Then read Transfer logs. |
