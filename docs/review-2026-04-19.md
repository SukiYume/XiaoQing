# XiaoQing QQBot 当前代码审查报告（2026-04-19）

## 范围

- 审查对象：`core/` 与全部 active plugins。
- 明确跳过的 deprecated 目录：`plugins/ads_deprecated`、`plugins/covid_deprecated`、`plugins/memo_deprecated`。
- 明确不计入本报告的问题：
  - `core/dispatcher.py` / `plugins/url_parser` 的 URL SSRF 问题
  - `plugins/shell` 白名单绕过
  - `plugins/minecraft` 普通成员可直接发 RCON
  - `plugins/qingssh` 明文密码落盘
  - `plugins/chat` 固定 Coze `user`

本报告基于本地代码阅读、定向复核、`pytest -q` 基线验证，以及多个 subagent 并行审查结果汇总。

## 验证基线

- 全量测试：`pytest -q`
- 当前结果：`1832 passed, 34 skipped`

结论不是“项目整体不可用”，而是“主干 happy path 基本可跑，但仍有一批真实的状态一致性、作用域隔离、失败路径和命令面正确性问题没有被当前测试体系拦住”。

## 总览

- 高优先级：10 项
- 中优先级：20 项
- 低优先级：10 项

主要风险集中在 6 类：

1. 配置与运行时状态的一致性不够稳。
2. 多用户 / 多群作用域隔离仍有破口。
3. 部分缓存和后台任务语义不正确，导致“读到旧数据”或“重置后被写回”。
4. 若干命令的参数解析与用户看到的行为不一致。
5. 若干连接失败路径会泄漏资源或错误报成功。
6. 仍存在重复的 JSON / 状态持久化实现，错误处理口径不统一。

## 高优先级问题

### Core / 框架

- `core/onebot.py:198-216`，`core/app.py:504-509`
  - 问题：WS 发送失败时只记日志，不清理 `_ws`，`_send_single_action()` 仍把 WS 视为可用并直接返回。
  - 影响：消息不会降级到 HTTP sender，出站动作会被静默丢弃。

- `core/config.py:91-113,205-207`，`core/plugin_base.py:108-116`
  - 问题：`config.json` / `secrets.json` 解析失败被当成 `{}`，不是“保留最后一次有效配置”。
  - 影响：一次损坏写入或手工编辑失误就可能把 bot 设置、管理员列表、token 全部清空到运行时快照。

- `core/config.py:126-158`
  - 问题：`update_secret()` 先改内存，再落盘；若 `save_secrets()` 失败，没有回滚。
  - 影响：内存里的 secret 已变更，但磁盘仍是旧值，运行时状态与持久化状态分裂。

- `core/onebot.py:174,296-297,355,370-371`
  - 问题：`max_pending_events` 没有真正限制 handler 执行并发。
  - 影响：信号量只包住入队过程，不包住 `_drain_queue()` 中的实际处理；高基数消息洪峰下会突破预期并发上限。

### 插件

- `plugins/qingpet/main.py:384-415`
  - 问题：私聊入口仍把缺失群号归一成真实的 `group_id=0`，并把它传给大量以群为隔离键的 handler。
  - 影响：私聊 `/宠物 购买`、背包、交易、社交等会把数据写进 group `0`，污染状态且破坏真实群作用域。

- `plugins/pendo/main.py:111-119,899-918`，`plugins/pendo/utils/db_ops.py:27-59`，`plugins/pendo/web/deps.py:7`
  - 问题：Web UI 启动时拿一个 `Database` 实例，bot 命令路径又通过 `get_database()` 拿另一份实例。
  - 影响：两边各自维护缓存；bot 侧编辑 / 删除后，Web API 可能继续返回旧数据直到 TTL 过期或重启。

- `plugins/adnmb/main.py:51-70`，`plugins/adnmb/adapi.py:180`
  - 问题：`AdnmbClient` 缓存在插件级 `state`，feed 订阅操作又只按单个 UUID 工作。
  - 影响：同一 bot 进程内的不同用户会互相影响订阅列表，实际共享 feed 状态。

- `plugins/ads_paper/storage.py:177-193`，`plugins/ads_paper/note_commands.py:181-221`
  - 问题：deadline 展示时按日期排序，但删除时按原始插入顺序删。
  - 影响：用户按列表序号删除时可能删错截止日期。

- `plugins/arxiv_filter/main.py:354-357`，`plugins/arxiv_filter/arxiv_today.py:228-230,249-250`
  - 问题：最后一次检查把“日期探测失败（`None`）”当成“今天没更新”，并直接 `_mark_sent_today()`。
  - 影响：一次瞬时抓取 / 解析失败会让当天后续所有重试都被抑制。

- `plugins/minecraft/main.py:289-293`，`plugins/minecraft/rcon.py:122`
  - 问题：`RconClient.command()` 在连接 / 认证 / 传输失败时会返回 `None`，但调用方把它当成“命令执行成功但无输出”。
  - 影响：真实失败会向用户回 `✅ 命令已发送（无返回）`，误导性很强。

## 中优先级问题

### Core / 框架

- `core/server.py:229-269`
  - 问题：Inbound HTTP / WS 接口接受任意 JSON 值，然后把数组 / 字符串这类非对象 payload 继续传给 dict-only 处理逻辑。
  - 影响：合法 JSON 但结构错误的请求会变成 500，而不是明确的 4xx。

- `core/app.py:470-497`
  - 问题：出站消息 preview 日志没有做敏感信息 masking。
  - 影响：消息文本里若带 token、密码、验证码等内容，会原样进入 info 日志。

- `core/app.py:292-299,767-789`，`core/server.py:97-108,179-200`
  - 问题：`InboundManager.set_status_providers()` 只定义未接线。
  - 影响：`/metrics` 仍会返回 `501 Metrics not configured`，`/health` 也不会暴露预期的插件 / session / job 状态。

- `core/plugin_manager.py:179-192`
  - 问题：取消异步 `init()` 任务时，如果插件还没进入 `_plugins`，会直接返回，跳过 `_pending_plugins` 清理和模块 purge。
  - 影响：再次 reload 时可能复用半初始化模块状态。

### xiaoqing_chat / pendo / qingpet

- `plugins/xiaoqing_chat/task_scheduler.py:38-50`，`plugins/xiaoqing_chat/handlers.py:1004-1007`，`plugins/xiaoqing_chat/main.py:157-179`，`plugins/xiaoqing_chat/memory/memory.py:57-128`
  - 问题：`/xc 重置` 和 shutdown 不能真正阻止已经进入 `asyncio.to_thread()` 的持久化写入。
  - 影响：刚清空的历史可能被后台线程重新写回；同时 shutdown 时最近消息也可能来不及持久化。

- `plugins/xiaoqing_chat/handlers.py:425-449,481-483`，`plugins/xiaoqing_chat/expression/bw_reflect_tracker.py:185`
  - 问题：expression reflection 在 `_should_reply()` 之前就启动。
  - 影响：本来不会回复的环境噪音消息也会触发额外的反思 / LLM 开销。

- `plugins/pendo/services/db.py:764-767,810-813,1413-1415,1439-1440`
  - 问题：缓存读路径用了 `if cached:`，把 `None`、`[]` 等 falsy 缓存值当成 miss。
  - 影响：空用户、空结果、缺失项这些常见路径仍会反复打 SQLite。

- `plugins/qingpet/main.py:207-230,399-411`
  - 问题：私聊流量还共用 `group_id=0` 的限流 / 反刷屏桶。
  - 影响：一个用户的私聊宠物操作可能无意抑制另一个用户的私聊命令。

### qingssh / jupyter / minecraft / shell

- `plugins/qingssh/handlers.py:213-219`
  - 问题：当已有 `qingssh` session 时，`/ssh disconnect <name>` 总是断当前 session 服务器，而不是你显式指定的那个名字。
  - 影响：命令面行为与用户预期不符。

- `plugins/qingssh/ssh_manager.py:567-620`
  - 问题：跳板机连接成功后，若最终目标机 `connect()` 失败，异常路径不会关闭临时 jump client。
  - 影响：失败连接会泄漏一条跳板机连接。

- `plugins/jupyter/jupyter_manager.py:48-75`
  - 问题：Jupyter kernel 单例缓存 key 只包含 `owner_key`，不包含 `data_dir`。
  - 影响：同一 owner 在不同 workspace / data dir 下会复用旧 kernel 和旧 figures 目录。

- `plugins/minecraft/main.py:204-225`
  - 问题：先建立 RCON，再校验可选日志文件；日志参数非法时直接返回，不做 `disconnect()`。
  - 影响：失败连接路径会残留一个活跃 RCON 连接。

- `plugins/shell/config.py:19,110`，`plugins/shell/main.py:223-235`
  - 问题：白名单包含 `dir`、`cd`、`copy`、`del`、`type`、`help`、`jobs` 等 shell built-in，但执行器始终走 `create_subprocess_exec()`。
  - 影响：这些命令能通过校验，却会在运行时直接失败。

### ads_paper / earthquake / astro_tools

- `plugins/ads_paper/storage.py:62-72,168-180`，`plugins/ads_paper/note_commands.py:39-41,219-220`
  - 问题：notes 和 deadlines 存了 `user` 字段，但读取和删除从不按 `user` 过滤。
  - 影响：同一插件实例内的用户可看到或删除他人的笔记 / 截稿日期。

- `plugins/earthquake/main.py:43-51,193-195`
  - 问题：`earthquake.json` 损坏时 `_load_since()` 没有 JSON 容错。
  - 影响：手动触发和定时任务都会直接抛 `JSONDecodeError`，直到文件被手工修复。

- `plugins/astro_tools/time.py:17-23,68-72`
  - 问题：数值时间解析仍会把 `< 1_000_000_000` 的合法 Unix 时间戳优先当成 JD。
  - 影响：如 `946684800` 这类时间戳会走错分支。

### 命令面正确性

- `plugins/dict/main.py:164-177`
  - 问题：`/dict -e <term>` 中，`-e` 吞掉了查询词，而 handler 最终又回退到 `args.strip()`。
  - 影响：精确匹配实际会拿字面量 `-e galaxy` 去查。

- `plugins/color/main.py:174-176`
  - 问题：`/color -t` 会把空参 flag 解析成 `"true"`。
  - 影响：无法命中“列出全部 spectral types”的空前缀分支。

- `plugins/choice/main.py:50-87`
  - 问题：`parse_choice_args()` 用的是裸 `split()`，不支持引号和多词选项。
  - 影响：`/choice pick "ice cream" pizza -n 3 -u` 这类输入会被拆坏。

- `plugins/chime/main.py:305-345`
  - 问题：除 `help` 外，其他参数基本都忽略，统一掉进相同的抓取 / 更新流程。
  - 影响：`/chime list`、`/chime FRB...`、拼错子命令都无法表现出命令面差异。

## 低优先级问题

### Core / 框架

- `core/server.py:76,313-316`
  - 问题：`_ws_event_locks` 只增不减。
  - 影响：长时间运行的 inbound server 会累积每个 `(group_id, user_id)` 的锁对象。

- `core/plugin_manager.py:356-365`
  - 问题：watcher 当前会监控插件目录下所有 `.json`，包括 `plugin_dir/data` 里的运行时状态文件。
  - 影响：启用 watcher 时，普通状态落盘也会看起来像“代码变更”，触发不必要 reload。

- `core/args.py:90-102`
  - 问题：负数值仍可能被误判为 flag / option。
  - 影响：依赖负数参数的命令面不稳。

### 插件

- `plugins/url_parser/main.py:88-92,116-117`
  - 问题：相对 OG / Twitter 图片 URL 没有基于页面 URL 解析成绝对地址。
  - 影响：依赖相对路径的站点会丢失图片预览。

- `plugins/twitter/main.py:296-297,363-376`
  - 问题：已缓存图片会被记成“空页”。
  - 影响：连续多页缓存命中时会过早停止翻页，漏掉更旧但尚未缓存的图片。

- `plugins/github/main.py:177-184`
  - 问题：star / fork 解析过度依赖 `a.Link--muted` 这类页面 class。
  - 影响：GitHub 改动 DOM 后计数会静默变成 `0`。

- `plugins/voice/plugin.json:4-16`，`plugins/voice/main.py:134-196`
  - 问题：插件说明宣称支持 STT，但生产命令只注册了 `tts`。
  - 影响：能力声明与真实命令面不一致。

- `plugins/shell/plugin.json:8-13`，`plugins/jupyter/plugin.json:8-13`
  - 问题：`shell` 广告了 `/exec` alias，但同触发词总被 `jupyter` 先命中。
  - 影响：这个 alias 实际不可达。

- `plugins/color/main.py:43-45`，`plugins/color/data_manager.py:23`，`plugins/color/stellar.py:69`
  - 问题：静态色彩数据每次请求都重读磁盘。
  - 影响：有不必要的重复 I/O。

## 横向评估

### 功能性

- 主框架、消息流、绝大多数 happy path 当前是可用的。
- 残留的功能性问题主要集中在：
  - 作用域错误：`qingpet`、`adnmb`、`ads_paper`
  - 失败假阳性：`minecraft`
  - 命令面不一致：`dict`、`color`、`choice`、`chime`、`shell`
  - 文档 / 能力声明不一致：`voice`

### 代码正确性

- 最严重的是“状态被错误地共享”与“缓存 / 配置语义不正确”。
- 这类问题跨越：
  - `core/config`
  - `pendo`
  - `qingpet`
  - `adnmb`
  - `ads_paper`

### 性能

- 当前最值得优先关注的性能热点：
  - `core/onebot.py` 的并发上限失效
  - `plugins/xiaoqing_chat/handlers.py` 在 reply gate 前启动 reflection
  - `plugins/color` 每次请求重读静态数据
  - `plugins/astro_tools/obj.py` 现在虽然不阻塞主事件循环，但全局 `RLock` 仍会把全部查询串行化

### 稳健性

- 失败路径仍然不够硬：
  - 配置文件损坏会被当成空配置
  - `earthquake.json` 损坏会直接打瘫插件
  - RCON / SSH 若干失败路径会泄漏连接
  - Inbound 非对象 JSON 会走 500

### 代码冗余与重复

- JSON 持久化仍未统一收敛到一套 helper。
- 当前仍有多处自写 `read_text()/write_text()/json.dumps()` 路径，例如：
  - `plugins/ads_paper/storage.py`
  - `plugins/earthquake/main.py`
  - `plugins/github/main.py`
  - `plugins/pendo/web/auth.py`
- `pendo` 还存在两条 DB 实例化路径，已经从“冗余”演变成“行为不一致”。

### 测试体系

- 当前全量测试是绿的，但仍偏：
  - happy path
  - mock 路径
  - 静态结构断言
- 还没有很好覆盖：
  - 多用户 / 多群隔离
  - 配置损坏与落盘失败
  - 背景线程持久化竞态
  - Web / bot 双实例缓存一致性
  - 失败路径资源回收
